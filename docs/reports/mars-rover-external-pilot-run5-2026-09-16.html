27. Local-Spec vs CodingDojo Differences

  • Command representation: local uses letters F/L/R in a string; CodingDojo describes arrow-emoji commands in a list — a notational choice, not a behavioral one.
  • Obstacle "does nothing" interpretation: local SPEC.md explicitly states only the blocked F is voided and subsequent commands continue; CodingDojo's own wording is silent on this exact point.
  • Public API shape: simulate(start, obstacles, commands) -> (x, y, direction) is a local addition — CodingDojo does not mandate any particular function signature.
  • Explicit "no wrap-around" statement: local SPEC.md states this directly; CodingDojo is simply silent on map bounds (not implemented, but also never required).
  • Coordinate axis convention (N=y+1, E=x+1, etc.): pinned explicitly in local SPEC.md; CodingDojo does not specify an axis convention.

None of these are presented as part of the official CodingDojo statement — they are local clarifications of points CodingDojo leaves open.
